## ¿Cuándo elegir Make?

Make es la opción más lógica si te identificas con alguno de estos perfiles:

- **No tienes perfil técnico en el equipo.** Make está diseñado para que alguien sin conocimientos de programación pueda construir automatizaciones complejas con un editor visual de arrastrar y soltar.
- **Quieres resultados en horas, no en días.** La biblioteca de plantillas predefinidas de Make cubre casos habituales de pymes: sincronizar contactos, enviar notificaciones, gestionar tareas. Partes de algo que ya funciona.
- **Tu stack es de herramientas SaaS estándar.** Make tiene más de 1.800 integraciones nativas. Si usas Holded, Google Workspace, Slack, Typeform o WooCommerce, casi seguro que hay conector directo.
- **No quieres gestionar servidores.** Make es 100% cloud. Pagas y funciona, sin instalar nada ni preocuparte de actualizaciones.
- **Tu volumen de automatizaciones es moderado.** El plan de entrada cubre 10.000 créditos/mes — suficiente para una pyme con 5-10 flujos activos.

---

## ¿Cuándo elegir n8n?

n8n tiene mucho sentido si tu situación es distinta:

- **Tienes un desarrollador o alguien técnico en el equipo.** n8n permite escribir código JavaScript directamente en los nodos, lo que abre posibilidades que Make no puede cubrir sin workarounds.
- **El volumen de automatizaciones es muy alto.** Si autoalojas n8n en tu propio servidor (o en uno de tu proveedor cloud), el coste es prácticamente cero, independientemente del número de ejecuciones.
- **Manejas datos sensibles y necesitas que no salgan de tu infraestructura.** Con la versión self-hosted, los datos de tus flujos no pasan por servidores de terceros — punto crítico si trabajas con datos personales bajo LOPDGDD.
- **Las integraciones que necesitas son muy específicas o de nicho.** n8n permite crear nodos personalizados desde cero, algo que Make no ofrece de forma nativa.
- **El precio a largo plazo importa más que la comodidad inicial.** Autoalojado en un VPS de 10-15 €/mes, n8n no tiene límite de ejecuciones ni usuarios.

### ✅ Funcionalidades principales

**Make:** Su punto fuerte es la potencia visual. Los escenarios se construyen como un diagrama de flujo real — se ven los datos en cada paso, se pueden probar rama por rama, y el sistema de filtros y routers permite lógica condicional sin escribir una sola línea de código. Las iteraciones sobre listas, el manejo de errores y los reintentos automáticos están bien resueltos.

**n8n:** Funciona con nodos conectados entre sí, similar en concepto pero con una capa de código debajo accesible si la necesitas. Lo que n8n hace que Make no puede: ejecutar JavaScript en cualquier nodo, crear nodos personalizados, y tener control total sobre la lógica de los flujos. Para casos complejos o muy específicos, n8n es más flexible.

**Automatizaciones complejas con datos estructurados:** Make maneja bien listas y arrays con su módulo Iterator, pero llega a su límite en transformaciones de datos muy elaboradas. n8n, con acceso a código, resuelve esos casos sin workarounds. Para una pyme con el perfil de Carlos — flujos de sincronización de datos, notificaciones, gestión de leads — Make cubre el 90% de los casos sin necesitar código.

Si Carlos tiene un problema un martes por la mañana, con Make tiene más opciones de encontrar respuesta en español en foros de comunidad. Con n8n, probablemente tendrá que leer la documentación en inglés o esperar respuesta del soporte oficial.

### Facilidad de uso

**Tiempo hasta ser productivo:** Con Make, la curva inicial es corta — alguien sin experiencia puede tener su primer flujo funcionando en 1-2 horas siguiendo una plantilla. Con n8n, el concepto es similar, pero la interfaz es menos pulida y la configuración de algunos nodos requiere más conocimiento técnico.

**Onboarding:** Make tiene un asistente guiado con plantillas para casos comunes desde el primer acceso. n8n en cloud tiene un onboarding básico; en self-hosted, partes de cero con la documentación.

**Curva de aprendizaje:** Make es intuible para alguien que viene de Excel y sabe lo que quiere conectar. n8n requiere entender cómo funciona la estructura de datos JSON para sacarle partido real — no es difícil si se tiene base técnica, pero es un freno para quien no la tiene.

### 🇪🇸 Integraciones con herramientas españolas

**Holded:** Make tiene integración nativa con Holded. n8n no tiene nodo nativo — habría que usar la API de Holded vía HTTP Request, lo que requiere configuración manual.

**Sage:** Ninguna de las dos tiene integración nativa con Sage 50. En ambos casos habría que usar la API si existe o exportar/importar ficheros.

**Factorial / Sesame:** Make tiene conectores para Factorial. n8n, mediante HTTP Request y la API de Factorial, también puede conectar — pero requiere más trabajo inicial.

**Verifactu / Facturación electrónica:** Ninguna gestiona facturación directamente — no aplica a esta categoría.

**WooCommerce / PrestaShop:** Make tiene nodos nativos para WooCommerce. n8n también tiene nodo nativo para WooCommerce. En este punto están igualados.

<Callout type="tip">
Si ya usas Holded como ERP, Make es la opción más directa: la integración nativa funciona sin necesidad de configurar APIs manualmente. Con n8n tendrás que hacer esa parte a mano.
</Callout>

## Veredicto por perfil

- **Equipo pequeño sin perfil técnico (1–8 personas):** Make — puedes empezar solo, con plantillas, sin ayuda externa.
- **Pyme con volumen alto de automatizaciones y alguien técnico en casa:** n8n self-hosted — el coste no escala y tienes control total.
- **Soporte en español es prioritario:** Ninguna de las dos tiene soporte oficial en español. Make tiene comunidad hispanohablante más activa — elige Make si esto importa.
- **Manejas datos personales sensibles (LOPDGDD):** n8n self-hosted — los datos no salen de tu infraestructura. Con Make, los datos pasan por servidores de Make (EE.UU./UE según configuración).
- **Ya usas Holded como ERP central:** Make — la integración nativa evita configuraciones manuales de API.
- **Presupuesto muy ajustado y tienes capacidad técnica básica:** n8n self-hosted en un VPS de 10 €/mes — sin límite de ejecuciones, coste fijo y bajo.

## Conclusión

La diferencia real entre Make y n8n no es de funciones — es de a quién van dirigidas.

Make es la herramienta para la pyme que quiere automatizar sin que eso sea un proyecto técnico. Se paga una suscripción, se usan las plantillas, y en pocos días tienes flujos funcionando. Para el perfil de Carlos — gestor, no informático — es la opción más sensata.

n8n es potente, flexible y muy barato si lo autoalojas. Pero necesita que alguien del equipo entienda lo que está haciendo. Si no tienes esa persona, acabarás con flujos rotos que nadie sabe arreglar.

Si tu caso es mixto — quieres empezar con algo manejable pero anticipas necesidades complejas — empieza con Make. Siempre puedes migrar más adelante cuando tengas claros los flujos que necesitas.

## Preguntas frecuentes

### ¿Make o n8n para una pyme sin perfil técnico?

Make, sin duda. El editor visual, las plantillas y la facilidad de configuración lo hacen accesible para alguien que no programa. n8n requiere cierta comodidad con conceptos técnicos para sacarle partido real.

### ¿Cuánto cuesta Make para una pyme española?

El plan de entrada (Core) cuesta 9 $/mes + IVA con facturación anual e incluye 10.000 créditos al mes, suficientes para muchas pymes que empiezan a automatizar. Make cobra en dólares: el coste exacto en euros varía con el tipo de cambio.

### ¿Es n8n gratuito?

n8n tiene una versión cloud con planes de pago desde 20 €/mes (Starter, facturación anual, 2.500 ejecuciones al mes); todos sus planes incluyen usuarios y workflows ilimitados, según su web, y el precio depende de las ejecuciones mensuales. La versión self-hosted — que instalas en tu propio servidor — es gratuita bajo su licencia de uso sostenible. El coste real del self-hosted es el del servidor (un VPS básico ronda los 10-15 €/mes).

### ¿Cuál de las dos cumple mejor con el GDPR y la LOPDGDD?

n8n self-hosted es la opción más segura en este sentido: los datos de tus automatizaciones no salen de tu infraestructura. Con Make, los datos pasan por los servidores de Make (empresa europea con DPA disponible bajo GDPR). Ambas opciones son compatibles con GDPR si se configuran correctamente, pero n8n self-hosted da más control para empresas que manejan datos personales sensibles.

### ¿Puedo migrar de Make a n8n más adelante?

Sí, pero no hay migración automática. Tendrás que recrear los flujos en n8n manualmente. Por eso tiene sentido empezar con Make si no tienes claro lo que necesitas — primero defines tus flujos, luego decides si necesitas la potencia de n8n.
